# Cubic TIP3P allocation-bound review

The change tightens a resource estimate; it changes neither the requested box nor the 100,000-atom limit. It is specific to the recorded installed OpenMM cubic TIP3P path with neutralization and zero added salt. No additional dynamics was run for this review.

I compared `tip3p_allocation_bound` with installed OpenMM 8.6 `Modeller.addSolvent`. Both calculate the solute-centered bounding radius with the same Vec3 and `unit.norm` arithmetic, then use width `max(2*radius + padding, 2*padding)`. For each oxygen in the installed three-site water template, the new helper counts each axis's admissible tile indices using the literal native inclusive test `oxygen + k*period <= width`, over the native range starting at zero. The product counts all candidate water molecules before exclusions. The comparison width advances two representable floats upwards, conservatively including boundary cases; the physical box width is untouched. Binary search avoids allocating a potentially huge tile grid.

The total bound is existing atoms plus three times the candidate water count. In this exact path, solute exclusion and periodic-edge filtering only remove waters, while neutralization replaces a three-atom water with a single monovalent ion. Thus those later operations cannot increase the bound. The helper validates one oxygen and two hydrogens per template residue, positive finite template dimensions, and finite input coordinates. Template SHA-256, OpenMM version, box dimensions, upper count and final actual atom count are recorded. The existing actual topology cap remains in force after native solvation.

Code inspection found no critical defect in that argument. The GPCR's unchanged 9.693596 nm cube has a candidate bound of 95,161 atoms; the former bulk-density estimate was 105,048. This does not prove that every solvation under the bound will succeed, or establish equilibrated solvent or receptor behavior. The planned actual solvation supplies the final count check.
