# Read-only integration review: automatic fragment-first loop repair

The smallest correct seam is an outer search around **complete candidate preparation and validation**, immediately after `PreparationWorker.prepare` has created the sequence-restored heavy-atom scaffold (backend/preparation_worker.py:508). Use `loop_search.run_candidate_search` to own private attempts, and keep dataset publication outside that search. Changing only `construct_loops` or catching the final `ValueError` is insufficient: the current generator stops after any closed fragment, while its later complete geometry rejection terminates preparation.

This review inspected sources only. It did not rerun archived validations, launch scientific calculations, change application code or qualify physical loop accuracy. Root's two reported archived 1UA2 passes remain subject to their separate artifact review.

## Coordinate and chemistry contracts

Keep two explicit baselines. The immutable requested source frame supplies observed backbone coordinates, sequence identities, retained molecules and protected contacts. A separately recorded common preparation reference may include declared heavy-atom completion and chi adjustments. An observed movement cap must name the baseline it uses, with total movement from the source also reported. The current research archive's `loop-refinement-input.npz` is a post-preparation seed, not proof of the original deposited full structure. Its source binding checks only the standard observed backbone within PDB rounding tolerance. Fresh integration must bind the full retained heavy-atom identity/element/graph inventory, modified residues, ligands, ions and waters to the job snapshot. Never make a native proposal its own reference.

Coherent native context must enter refinement together. Replacing moved context immediately with unrelated source atoms and then treating the spliced geometry as native is not the reviewed path. Restore only the declared outer-torsion support atoms, record that initialization, and require final checks. Mobile context is limited to immediate eligible standard protein flanks; metal-binding or chemically crosslinked residues remain protected. Unchanged external phi/psi/omega support must remain exact. New or actually changed reference definitions are checked regardless of whether the source was already an outlier. Unchanged source outliers are excluded by exact support-coordinate equality, never by their classification.

The research validator intentionally permits `candidate_selected <= modeled` because it replaces one loop while keeping other archived loops. That is insufficient for a new end-to-end preparation search. Require an explicit complete proposal for every requested missing stretch, or an explicitly bound full composite with every component's provenance. Do not fill absent loops from a rejected archived candidate. Multiple-gap proposals with overlapping contradictory context require rejection or a separately declared composition policy, not silent last-row replacement.

Native proposals remain heavy-atom-only. Reject unexpected H rows rather than silently accepting/skipping them. Preserve the complete topology's H-name/heavy-parent inventory and formal states, regenerate H only on changed/modeled residues, map the result back to canonical atom order, then check full atom/bond equality and unchanged retained coordinates. Hydrogens may relax later as currently documented. Unprovided canonical sidechains may use the existing proper residue-frame initialization with explicit provenance; this is not rotamer prediction. Retained ligand/modified/ion chemistry comes from the verified source parameter bundle, never the native model's standardized context.

The archived parameter check verifies present replay consistency, not historical protein/water XML identity. Fresh jobs should pin base protein/water XML and recursive includes when the common parameter bundle is created, alongside ligand/modified parameters and ordered per-atom charges. Recreate the unrestrained native system and verify it before/after each attempt and at publication. Never reuse a construction system as the simulation system.

## Retry, progress and cancellation

Use `CandidateUnavailable` only for an explicit bounded absence of a proposal. Use `Validation(checks, reasons, artifact)` for genuine complete-quality rejection. Source/atom/state/parameter integrity errors, malformed native results, runtime failure and programming exceptions stop the search. A broad `except ValueError: retry` would hide chemistry failures. Current native construction exceptions aggregate several error types, so they need explicit result classification before adaptation.

Both generation and complete validation need bounded child-process supervision with the parent polling cancellation/progress. `_minimize_attempt` performs native minimization without a cancellation callback; wrapping it only with pre/post `check_cancel` cannot enforce a search deadline while native work blocks. Reuse an already reviewed supervisor for both stages, with child/group cleanup, rather than copying the limited research runner. `loop_modeling._run` provides a 180-second generator timeout but no RSS gate or verified descendant cleanup after normal leader exit. These are supervision requirements for integration, not a request for another scientific campaign.

Bridge the cancellation types explicitly: `Worker.check_cancel` raises `Cancelled`, but `loop_search` recognizes `SearchCancelled` and the preparation worker recognizes `Cancelled`. Translate on search entry and exit so both records say cancelled and no next generator starts. Use the existing progress event fields (attempt, generator, stage, number/total) for messages such as “Checking loop model” and “Trying another reconstruction.” Keep overall preparation progress below completion until final promotion; retain all rejected attempt records. Users need no algorithm selector.

`ValidatedArtifact` currently binds one coordinate file. End-to-end publication also consumes topology, parameter and provenance sidecars. Bind these in a final manifest whose hash travels with the accepted result, and verify every required member before publication. Do not repurpose an unbound sidecar or infer the full bundle from a PDB hash alone.
