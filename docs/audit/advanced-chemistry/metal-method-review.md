# Metal-site preparation: implementation decision and evidence

Date: 2026-09-13. This is a software/method feasibility assessment, not a certification that any generated metal-site force field reproduces experiment. No new metal-site model is enabled in the released application by this review.

## Recommended first workflow

Implement a **site-specific, fixed-coordination bonded model for closed-shell Zn(II)**, beginning with an explicitly specified first coordination sphere. Use an open-source QM provider for the small-cluster optimized geometry/Hessian and a larger capped-cluster electrostatic potential; use native AmberTools MCPB Seminario and RESP routines for parameter extraction. Preserve the source structure, capping map, protonation/oxidation choices, QM inputs/results, fitted charges, bonded parameters, validation, and engine conversions as separate artifacts. The published MCPB workflow already follows this small-Hessian/large-ESP separation. [Amber MCPB tutorial](https://ambermd.org/tutorials/advanced/tutorial20/mcpbpy.php), [MCPB.py paper](https://doi.org/10.1021/acs.jcim.5b00674).

This model represents motion near a chosen coordination state. It does not predict coordination exchange, redox, catalysis, or bond formation/breaking. A metal–donor bond surviving a trajectory is an expected consequence of a bonded force field, not evidence that its parameters are physically accurate. [12–6–4 model paper](https://pmc.ncbi.nlm.nih.gov/articles/PMC4306492/).

## Alternatives and scope

| Method | Useful capability | Important limitation | DynaMol decision |
|---|---|---|---|
| Existing TIP3P 12–6 ion parameters | Ordinary named ions, validated ion charge/LJ identity | A bare hydrated-ion model does not establish an active-site coordination model | Keep existing scope; do not relabel as advanced site preparation |
| Site-specific bonded Zn | Explicit coordination graph, fitted bond/angle terms and site charges; ordinary Amber topology can transfer to both engines | Fixed coordination and cluster/state dependence; every site requires checks | First prototype |
| 12–6–4 | Adds charge-induced dipole interaction; potentially permits ligand exchange without explicit bonds | Ion–water calibration does not automatically transfer to every protein donor; pair-specific parameters matter | Separate future model, never silent replacement |
| Multisite/dummy Zn | Published structural coordination templates and directional electrostatics | Additional sites and geometry assumptions; template applicability must be established | Future explicitly named template family |
| Empirical MCPB Zn | Avoids a small-model QM Hessian | Still needs charge/state treatment and RESP in the documented workflow; limited calibration | No automatic shortcut for unvalidated donor chemistry |

The 12–6–4 literature documents both useful improvements and transferability limits. OpenMM's structural multisite Zn example is a concrete implementation for its stated structural-ion system, not general evidence for metalloproteases. [12–6–4 limitations study](https://pmc.ncbi.nlm.nih.gov/articles/PMC8339297/), [OpenMM multisite Zn tutorial](https://openmm.github.io/openmm-cookbook/latest/notebooks/tutorials/Histone_methyltransferase_simulation_with_multisite_Zn2_structural_ions.html).

## Current local implementation findings

- AmberTools **24.8**, MCPB script version **2024**, Python **3.14.7**, native `resp`, `respgen`, `tleap`, and `sqm` are already present under `.tools/ambertools`. Main application OpenMM is **8.6.0**, ParmEd **4.3.1**.
- `backend/ions.py` validates named integer-charge TIP3P 12–6 ions. `backend/complex_topology.py::metal_environment` identifies nearby donors/protected waters; those contacts are not site-specific fitted bonds. Its `subset` path removes monatomic-metal bonds.
- A RESP **partial charge** on Zn need not equal its formal **oxidation state** +2. Advanced site validation must compare the exact fitted charge map and whole-site charge, keeping oxidation state as separate metadata. The current bare-ion +2 check cannot be applied unchanged.
- MCPB reads Gaussian/GAMESS input formats. An adapter should call its native array-level Seminario routines and write the documented RESP ESP data format directly. It must not manufacture a Gaussian log to impersonate a different QM program.
- MCPB uses historical `B_TO_A=0.529177249`. Transfer coordinates and Hessians in atomic units directly and record that conversion constant; do not silently rescale provider arrays. Amber's `k(r-r0)^2` convention already contributes a factor of one-half in native Seminario; engine conversion must preserve the conventional factor of two for OpenMM harmonic forces.
- OpenMM's Amber reader supports C4 coefficients, but ParmEd documents limitations in reconstructing custom nonbonded forces. The current OpenMM-to-GROMACS route must not discard or approximate a 12–6–4 term. [ParmEd OpenMM conversion documentation](https://parmed.github.io/ParmEd/html/openmmobj/parmed.openmm.load_topology.html).

These statements are based on the installed source, not assumed from package names. File hashes and source URLs are recorded in `metal-method-evidence.json`.

## QM provider and cost

Use private-environment **PySCF 2.14.0** for the first prototype. Its analytic RKS Hessian and Mac/Linux support suit this machine. Select **B3LYPG** explicitly when comparing the Gaussian B3LYP reference: PySCF distinguishes the Gaussian-compatible and VWN5 variants, and a configurable generic alias is insufficient provenance. Record resolved functional, basis/ECP, charge, spin, grid, convergence and units. [PySCF installation](https://pyscf.org/user/install.html), [analytic RKS Hessian source](https://pyscf.org/_modules/pyscf/df/hessian/rks.html), [functional aliases](https://pyscf.org/_modules/pyscf/dft/libxc.html).

PySCF documents no native Windows support; Windows packaging requires WSL or another provider. Psi4 provides native Windows and Apple Silicon distributions, but its documented DFT method table lists energy/gradient rather than an analytic Hessian; finite-difference Hessians may cost many gradient evaluations. Choose after measured benchmarks, not a promise of identical installation/runtime. [Psi4 distributions](https://psicode.org/installs/v1102/), [Psi4 method capabilities](https://psicode.org/psi4manual/master/introduction.html).

The initial compute cap is two threads and 8 GB, with explicit job deadlines and progress. The published reference small model has **76 atoms and 684 basis functions**; its full optimized DFT/Hessian calculation is substantially more than a tiny smoke test. No runtime has yet been established on this machine. Begin with derivative checks on small molecules, then the reference's fixed geometry, then the site. PySCF's repository license is Apache-2.0; AmberTools has mixed component licenses. Keep third-party license notices/source obligations in the eventual package; this review is not legal advice. Raw license sources and hashes are saved under `license-source-notes/`.

## Gaussian reference basis and the distinct PySCF model

The actual native reference FCHK shell list contains **40 Cartesian d shells (6D) and one spherical f shell (7F)**, giving **684 AOs**. An earlier interpretation of its scalar shell metadata was incorrect; the explicit shell-type array resolves the convention. Stock PySCF `6-31g*` gives **644 AOs** with spherical shells or **687 AOs** with all Cartesian shells. Consequently, the spherical PySCF screening request is a **distinct documented method**, not a same-basis reproduction of that Gaussian calculation. B3LYPG naming alone does not remove this basis difference.

A Cartesian-AO calculation projected into a fixed mixed-shell subspace appears technically possible, but gradients, coupled-perturbed response and Hessians would require independent verification. No such implementation or derivative-equivalence claim is made. Native Hessian-to-Seminario parity is already established directly from the original reference arrays; reproducing that reference SCF is not a prerequisite for testing a separately specified spherical model.

## First site: human MMP8, PDB 1MNC

The fixed panel's input is a 2.1 Å human MMP8 structure. Its deposited same-image coordination records identify catalytic Zn A:281 coordinated to His218 NE2, His222 NE2, His228 NE2 and inhibitor PLH280 O1/O2; structural Zn A:282 has His168 NE2, Asp170 OD2, His183 NE2, His196 ND1; Ca A:283 has six listed protein oxygen contacts. The CIF and source hash are retained. [Structure's primary report](https://doi.org/10.1038/nsb0294-119).

The hydroxamic-acid inhibitor needs an explicit, documented bound protonation model. A neutral CCD component descriptor is not a determination of the metal-bound protonation state. Histidine tautomers must leave the coordinating nitrogen available. Cluster cutting must preserve complete coordinating functional groups, sensible caps, original-to-cluster identity, and a declared total charge/multiplicity. The catalytic Zn, structural Zn, and Ca are separate model decisions; validating one does not validate the others. This is currently a **prototype input**, not a prepared, validated complex.

## Acceptance gates

1. **Identity and chemistry:** preserve source identifiers and observed atoms, explicit donor graph, ligand bond orders, formal/protonation state and cap map; reject ambiguous/unreviewed state rather than silently guessing.
2. **QM quality:** converged SCF/optimization, finite derivatives, symmetry/unit checks, appropriate stationary-point diagnostics, preserved intended coordination; no raw-crystal Hessian presented as an optimized minimum.
3. **Adapter reference:** reproduce published native MCPB force constants and RESP data/charge fitting from preserved reference inputs; label this as implementation parity, not new-site validation.
4. **Model fit:** inspect physically meaningful modes and held-out local distortions/forces; record residuals and retained parameter provenance. Agreement between engines tests conversion, not the QM model's adequacy.
5. **Engine fidelity:** native Amber topology and independent energy/force comparison with OpenMM and GROMACS at multiple perturbed configurations; unchanged graph, atom order, exclusions and charges. No approximate replacement after a failed conversion.
6. **Motion:** bounded unrestrained solvent tests, repeated seeds, finite full-system forces, monitored coordination/bonds/geometry and broad structural integrity. Position restraints alone cannot establish a useful site model. No production-run or catalytic-validity claim follows from short trajectories.

Metallicious is useful open-source prior art for template matching and parameterization architecture, but its documented emphasis and reported validation are supramolecular metal-organic systems; it is not evidence of broad protein/metalloprotease preparation support. [Metallicious documentation](https://metallicious.readthedocs.io/en/latest/usage.html), [primary paper](https://pmc.ncbi.nlm.nih.gov/articles/PMC11500408/).

## Immediate deliverable

An isolated native-MCPB array/ESP adapter and a reproducible report against the official 1OKL reference precede any integration. The 15-case fixed metal panel will retain every outcome, including cases requiring a different oxidation, spin, coordination or cofactor model. The first validated family should be presented narrowly; one successful Zn complex will not support an “all metals” claim.

## Actual prototype results

- `reference-mcpb-1okl/adapter-parity-report.json`: all **18** published Seminario terms (four Zn bonds and 14 angles) reproduce at the published decimal precision. Independent FCHK coordinate/Hessian parsing agrees exactly with native MCPB parsing. Array-written RESP data for **113 atoms/3,540 points** are byte-identical to native extraction from the genuine published Gaussian log. Four malformed-input guards reject their inputs.
- `reference-mcpb-1okl/resp-parity-report.json`: both current native RESP stages converge, and all **113** array-path fitted charges agree exactly with direct current-native fitting using the original extracted ESP. However, the tutorial's historical **82** standard-model mol2 charges differ by up to **0.173776 e**. This historical mismatch is unresolved; published RESP-charge parity is **not** established. Native regenerated small/large initial geometries have the same atom order and coordinates as the published input files. These results do not validate new PySCF energies or a new site model.
- Native RESP revealed two practical runtime failures: long absolute input filenames are truncated by its fixed-width buffers, and its arm64 binary intermittently fails in the dynamic loader. The adapter preserves original inputs under short local names and requires actual convergence, not just exit code zero. `size -m` shows **2,074,737,104 bytes** of static common storage; the loader symptom matches a documented macOS large-static-Fortran failure. A dynamically allocated source-build candidate subsequently passed ten two-stage native-reference fits (20 launches), with all 113 fitted charges exactly unchanged; repeated failed launch logs remain available. The tested candidate is `build/advanced-chemistry/resp-runtime/heap-v2/resp`, with its validation report in the sibling `heap-v2-checks` directory. [GCC reproducer and dynamic-allocation observation](https://gcc.gnu.org/pipermail/gcc-bugs/2025-May/914852.html).
- `prototype-1mnc-inputs/cluster-input-report.json`: native MCPB constructs a **97-atom** small model and **139-atom** large model for the catalytic site, retaining the full inhibitor. The explicitly proposed state is Zn(II)/singlet, three neutral NE2-coordinating HID residues, and PLH O1 hydroxamate anion; the cluster charge is +1. Five source coordination edges match exactly, PLH C3(R)/C9(S) agree with the CCD, and source heavy coordinates are preserved through input construction. Capping identities are recorded separately. This is only an isolated cluster input; no QM calculation, full-complex preparation or dynamics is claimed. The two earlier input-format/rounding attempts are retained.

## Complete published-template milestone: 1CA2

The official ZAFF table identifies **1CA2 itself** as the reference for center6 (neutral water) and center7 (hydroxide). The water prototype uses the unmodified center6 templates: His94/HD4, His96/HD5, His119/HE2, water263/WT1 and Zn262/ZN6. Its backbone contacts independently confirm the distinct histidine mapping. The frozen source has no crystallization-pH field: water is an explicit benchmark model, and hydroxide remains a separate documented alternative. Neither the CCD nor this prototype determines the actual protonation equilibrium. [Official ZAFF template instructions and files](https://ambermd.org/tutorials/advanced/tutorial20/ZAFF.php).

`prototype-1ca2-zaff-water-v3/preparation-report.json` records a complete native **4,534-atom** protein/Zn/crystal-water model. All **2,207** original heavy atoms remain, with only PDB rounding on native serialization. The four Zn–donor bonds, every native bond/angle/torsion, charge, mass, Lennard-Jones term and exclusion match the unconstrained OpenMM system. The validator explicitly distinguishes Amber's ordinary-water H–H geometry terms from chemical topological bonds; Zn bonds retain the strict topology requirement. Initial failed input/naming reports remain available.

The full-system Sander check initially failed a 0.001 kJ/mol absolute energy gate by about 0.002 kJ/mol. Pinned native `set.F90::dihpar` explicitly evaluates phases within 0.001 radians of pi at exact pi, whereas OpenMM uses the stored historical value 3.141594. A diagnostic copy matching native phase and electrostatic conventions reduces the three-pose energy differences to **2.8e-6 kJ/mol** and maximum force differences to **3.9e-6 kJ/mol/nm**, satisfying the original gates. The production parameters and original failed comparison are unchanged; the diagnostic and a coordinate-independent phase-error bound are in `sander-native-phase-diagnostic.json`. This establishes mechanical conversion consistency, not chemical accuracy.

The complete model finished two short, unrestrained **5-ps OpenMM runs** and one **5-ps GROMACS run** in a **34,414-atom** water box. All 153 saved frames have finite forces and retain the four Zn bonds within declared broad geometry alarms. Maximum aligned Cα RMSDs are 0.611/0.573 Å (OpenMM) and 0.611 Å (GROMACS). These are **initial smoke checks**, not equilibrated stability evidence. Retrospective kinetic/temperature checks reproduce **70,866 mobile degrees of freedom**, and identify a low initial density of **0.8141 g/mL**. A separate longer NPT stage is therefore required before the comparison window. Original reports remain unchanged; their separate thermodynamic assessments record this limitation.

## Structural MMP Zn reference recovered

The exact published center9 reference is **2USN**, a human stromelysin-1 structure. Its HD8/His151, AP2/Asp153, HD9/His166 and HE5/His179 correspond to 1MNC His168, Asp170, His183 and His196. The 38 coordinating-residue heavy atoms align at **0.242 Å RMSD**. Context mapping matters: center9's backbone-H-bonding HID is **HD9**, unlike center6's **HD4**. Therefore a generic first-HID heuristic would assign the wrong charge/template map. The original reference CIF, official template table and comparison are preserved under `reference-zaff/`; this is a transfer candidate for the structural site, not acceptance of the five-coordinate catalytic site or the whole MMP complex. [2USN structure and primary citation](https://www.rcsb.org/structure/2USN).

`metal-panel-method-map.json` and its readable companion map all 15 fixed metal cases to actual published/installed model candidates or unresolved method/state boundaries. No case is removed or declared successful merely because one site has a model.

## GROMACS conversion checkpoint

The native GROMACS topology retains the exact atom inventory, metal bonds, site charges and all exclusions. Its OpenMM reader omits 4,265 exactly zero-amplitude torsions; the validator records these explicit no-ops and still requires every nonzero term and the full native exception list. Actual positive-periodicity and missing-nonzero-term guards remain active. Across four poses, original Amber versus exported GROMACS topology evaluated by the same OpenMM Reference implementation differs by at most **0.000652 kJ/mol** in energy and **0.001732 kJ/mol/nm** in force, within the original engineering gates.

The actual bundled GROMACS executable uses **mixed precision**. Its four-pose raw energy differences are **0.0028–0.240 kJ/mol**, with maximum force differences **0.0080–0.0669 kJ/mol/nm** and RMS force differences **0.0016–0.0021 kJ/mol/nm**. These raw numerical differences remain visible in `prototype-1ca2-gromacs-static/native-static-matrix.json`; they are distinct from parameter conversion and do not establish experimental model accuracy. The initial periodic-image misuse in a diagnostic reader is preserved with its failed result; subsequent comparisons use the identical saved coordinates without box-crossing artifacts.

## Solvent warm-up before engine comparison

An unrestrained **50-ps GROMACS NPT** stage at 300 K and 1 bar uses the complete unchanged 34,414-atom native model, v-rescale temperature coupling and stochastic cell rescaling. Its final 10 ps average **300.24 ± 1.66 K**, **1.02541 ± 0.00227 g/mL**, and **10.6 ± 177.6 bar** (sample standard deviations, not independent-sample confidence intervals). All 51 saved full-force frames are finite; the four zinc distances remain within the declared broad alarms, and the maximum aligned Cα RMSD is 0.744 Å relative to this stage's initial protein. Coordinate reconstruction uses the native bonded graph and checks every periodic bonded cycle.

The initial low density relaxed, but potential-energy means across the last three consecutive 10-ps blocks were −429445, −429939, and −430354 kJ/mol. Therefore this endpoint was **not automatically accepted by duration**: `prototype-1ca2-gromacs-npt50/comparison-readiness.json` records an additional bounded 25-ps NPT stage. That additional stage completed with final-window averages of **300.88 ± 1.30 K**, **1.02423 ± 0.00173 g/mL**, and **16.3 ± 174.3 bar**. Its potential-energy slope is +2.96 kJ/mol/ps, with a 495 kJ/mol sample standard deviation; the earlier sustained downward trend is no longer present. All 26 saved full-force frames and zinc geometry alarms passed. This supports starting a **short comparison**, not declaring full thermodynamic convergence.

The reviewed endpoint has volume **342.423819 nm³** and density **1.024546 g/mL**. Both **20-ps** comparison specimens completed using these coordinates and a fixed box, with separately documented thermostats and seeds. GROMACS/OpenMM mean temperatures are **300.02/300.67 K**, and maximum aligned Cα RMSDs are **0.707/0.728 Å**. Both have finite sampled full-system forces and clear zinc geometry alarms. Actual runtime volumes and independently recomputed kinetic temperatures agree with the recorded values. Original GROMACS coordinates/box match the source endpoint exactly; OpenMM only adds integer periodic images and a **5.63e−7 nm** maximum constraint projection.

`prototype-1ca2-warmed-comparison.json` records the actual checks, all six zinc-centered angles, exact source hashes, and the separate unresolved periodic-energy diagnostic. GROMACS samples full geometry/forces every 1 ps, while OpenMM additionally checks them every 0.1 ps; minima are not statistically comparable without accounting for this sampling difference. Final-window energy slopes remain visible (+78.0 kJ/mol/ps GROMACS, −23.6 OpenMM). These are short engineering specimens from one starting conformation per engine, **not converged thermodynamics or independent chemical-model validation**.

## Periodic-energy diagnostic remains separate

At the common full-solvent starting geometry, OpenMM CPU and Reference energies agree within **0.095 kJ/mol**, but actual mixed-precision GROMACS shows a settings-dependent absolute energy offset. Matching its Ewald coefficient, spline order and mesh to OpenMM reduces full-force RMS/max differences against OpenMM Reference to **0.00590 / 0.02430 kJ/mol/nm**, while an absolute **+24.64 kJ/mol** energy difference remains. Other retained GROMACS mesh/settings cases have energy differences of −37.33 and −70.43 kJ/mol. Bonded terms, charge identity and the small dispersion-correction convention difference have been checked separately.

`prototype-1ca2-periodic-diagnostic/periodic-comparison-matrix.json` retains the original values and input hashes. Independent component localization places the large offset mainly in direct-space Coulomb/exclusion/self-energy, rather than the reciprocal mesh contribution. The bundled mixed runtime changes energy by **41.72 kJ/mol** between one and two CPU threads despite bitwise-identical coordinates and very similar forces.

A separate pinned-source **double-precision** GROMACS 2025.4 build now reduces that thread difference to **2.56e−7 kJ/mol**, with a thread-force RMS difference of **3.47e−13 kJ/mol/nm**. Both zero-step evaluations use the unchanged original TPR and reproduce its coordinates and box exactly. Against OpenMM Reference, the raw double-native total-energy difference is **−0.408748 kJ/mol**, and full-force RMS/max differences are **0.001243 / 0.007062 kJ/mol/nm**. The independently measured dispersion-correction convention accounts for −0.457012 kJ/mol of the energy comparison; **+0.048263 kJ/mol remains after identifying that component**. This is descriptive decomposition, never a corrected pass value.

The large discrepancy is strongly consistent with native numerical accumulation. The double build also uses a different compiler and disables unused optional analysis components, so precision was not literally the sole build variable. Its input TPR still contains values serialized in single precision. **Exact absolute periodic parity remains undeclared**, and all original failures remain available. The new report and complete build/output provenance are in `prototype-1ca2-periodic-diagnostic/double-precision-discriminator.md/.json` and `build/advanced-chemistry/gromacs-double-v1/`. No installed engine, native source, production parameter or prior motion result was changed.
