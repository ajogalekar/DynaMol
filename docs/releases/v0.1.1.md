# DynaMol 0.1.1 — Mac packaging repair and missing loops

The 0.1.0 Mac installer was withdrawn after a packaging signature error caused macOS to report “DynaMol is damaged.” This replacement repairs the bundle seal and adds a bundled, offline loop-building runtime.

The self-contained app now includes these changes:

- The complete app is sealed after all its contents are finalized.
- Strict signature-integrity checks are required before archiving, after extraction, and after copying the app from the installer.
- Python bytecode writes inside the app bundle are disabled so running the app does not alter its sealed contents.
- Optional loop building supports up to **12 sequence-supported standard residues per internal gap, 96 total**, using ProMod3 fragments and bounded OpenMM refinement. Complete-complex geometry and chirality checks must pass; simulation minimization remains required.

For **Apple Silicon with macOS 14+**, open the DMG, drag DynaMol to Applications, then open the app. Python, OpenMM, GROMACS, AmberTools and ProMod3 are included; first-run private runtime setup opens the interface in your browser. No separate engine installation is needed.

Actual preparation passed for the 1UA2 monomer and four-chain structure, retaining ATP/TPO parameters and rebuilding 12 and 48 residues respectively. Each saved result passed 14 checks. A separate 12-residue ubiquitin deletion control also passed. These are approximate starting models, not verified native loops. See the [loop validation record](../audit/loop-repair/REVIEW.md) and [installation limits](../PACKAGING.md). The package retains its 100,000-atom limit and water-box workflow; it does not add membranes or GROMACS complex parameter export.

Apple explains the requirement to sign the outer app last and keep signed bundles unchanged in [Technical Note TN2206](https://developer.apple.com/library/archive/technotes/tn2206/_index.html).

The app still has **no Developer ID signature or Apple notarization**. Its ad-hoc signature checks package integrity; it does not establish Apple-trusted developer identity. For a trusted replacement download, macOS may still require **System Settings → Privacy & Security → Open Anyway**, following [Apple’s per-app opening guidance](https://support.apple.com/en-us/102445). Managed devices may restrict this option.

The earlier repaired installer passed a manual download and normal per-app opening check. The expanded package containing ProMod3 needs its own matching acceptance record; that earlier result does not automatically validate a changed payload. Consult the checksums and validation records beside the release assets for the exact build and completed checks. Local development-Mac tests do not establish independent clean-Mac compatibility.
